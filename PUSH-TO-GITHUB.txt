------------------------------ (a) HTTPS + Personal Access Token ----------------
Create a token: github.com -> Settings -> Developer settings ->

git push -u origin main
# when prompted:
#   Username: <user>
#   Password: <paste the Personal Access Token>        <- NOT your account password

# Optional: cache it so you only paste once

------------------------------ (b) SSH KEY  ------------------------------------
# This box currently has NO ssh key, so create one first:
ssh-keygen -t ed25519 -C "you@example.com" -f ~/.ssh/id_ed25519 -N ""
cat ~/.ssh/id_ed25519.pub
# -> copy that output into github.com -> Settings -> SSH and GPG keys -> New SSH key

# smoke test the key:
ssh -T git@github.com          # expect: "Hi <user>! You've successfully authenticated"

cd /home/amnotacat/vans-xss-github
git remote add origin git@github.com:<user>/vans-xss-poc.git
git push -u origin main

--------------------------------------------------------------------------------
NOTES / GOTCHAS
--------------------------------------------------------------------------------
* raw.githubusercontent.com sends Acecss-Control-Allow-Origin: * -> the app's
  cross-origin fetch works. It also sends Content-Type: text/plain for .json/.svg,
  which is FINE: the app fetches the body as text and JSON.parse()s / innerHTMLs
  it (it does not rely on Content-Type).
* If you edit a payload later, remember the jsdelivr/raw CDN caches. raw.github-
  usercontent.com is effectively uncached per-branch; if you use jsdelivr bump
  the @ref (e.g. @main -> @<commit-sha>).
* Do NOT commit base.txt / logs (already in .gitignore).
* Re-running tools/setbase.sh with a different user/repo/branch rewrites every
  URL in the tree and is safe to repeat.
